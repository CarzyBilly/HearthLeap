Hs LegendRush 0.1.2：本轮修复与未完成项
日期：2026-10-06

已修改
1. 自动检测：运行进程、已保存路径、32/64 位注册表和常见目录。
   使用低权限进程路径查询；发现后立即回填并保存两个路径。
   多个同安装目录炉石实例时不按随机枚举顺序选择账号。
2. 顶部导航：固定 62 DIP 行原先只剩约 38 DIP，却放了至少 42 DIP 的按钮。
   改为自动行高、44 DIP 按钮、上下 12 DIP 动效余量，保留悬停动画。
3. 删除“减少交互动效”勾选项与“从盒子建议到游戏动作”说明卡。
   动效仍遵守 Windows 的系统动画/辅助功能设置。
4. 操作按钮、运行状态和运行日志只出现在“引擎分析”。
5. 绑定判断：旧助手日志 PID 不能当作当前活动账号。
   比较盒子与游戏 PID、启动时间、助手事件时间及覆盖层。
   同一已核实会话可复用；活动其他客户端冲突仍拒绝，不能删掉账号隔离保护。
   未确认只等待最多 8 秒，支持停止，不再虚假提示“将自动完整重绑”。
   没有删除盒子账户配置、注销账号或自动关闭游戏。
6. 明确显示真实推荐源；可操作阶段缺建议 30 秒时：
   非只读停止，不猜测出牌；只读仅提示并继续观察。

AI3.0：尚未实现，不是已修复项目
维护版 Automation.cs 固定创建 NeteaseBoxRecommendationSource：
读取盒子本机 CEF 中已有的推荐。
老版 NeteaseNativeConstructedStrategy 使用
NeteaseDirectRecommendationSource(new Ai3PredictStateSource())：
收集局面、加载服务鉴权资料并发出 HTTP 推荐请求。
这不是同一个引擎；老版可以用 AI3.0，不能证明本机推荐源也会产生数据。
用户提供日志中 Bridge 连接成功、ReadProcessMemory 成功，而 payload 数始终为 0。
不能由此断言服务器拒绝原因，也不能承诺再次安装插件就能解决。
本包没有复制鉴权缓存、抓取 Cookie 或迁移服务权限/限额绕过，没有伪造 AI3.0 开关。
要接入服务端推荐，需要明确可用的接口契约及相应接口使用权限。

验证与范围
80/80 离线自检，包括 17 项进程绑定证据测试、5 项路径测试、3 项缺推荐测试。
隐藏 GUI 检查 1160×810 与 960×700；主要控件无需滚动即可操作。
测试导航实际分配高度、上下动效余量和布局裁切。
另输出 100%、125%、150%、200% 悬停渲染；不是对所有真实显示器 DPI 的人工验收。
检查路径回填/保存、三个页面状态隔离、设置验证、卡组输入与选择、关闭事务。
真实对局、盒子账户登录状态及绑定误判的实机回归仍待验收。
本轮未启动游戏对局、未安装真实插件、未请求第三方推荐服务。

现有 0.1.1 Bridge 已连接时不必为了这次界面/连接修复重复安装插件。
