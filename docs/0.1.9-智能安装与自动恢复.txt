HearthLeap 0.1.9：智能安装与自动恢复

本次修改
1. 点击“开始脚本”后自动检查 Bridge 插件完整性（文件、启动文件、SHA-256）。完整时跳过写入；缺失或校验不一致时自动安装/修复。
2. 日志使用“正在识别并智能安装插件…”、“插件已安装且完整，跳过安装。”、“未检测到完整插件，正在自动安装/修复插件…”等简短中文提示。
3. 炉石正在运行且插件缺失时不会热替换游戏目录：脚本等待炉石退出，自动完成安装后继续等待下一次正常启动；用户无需再次点击“开始脚本”。
4. 盒子与当前炉石绑定证据在 8 秒内未确认时，只在能够确认当前炉石、盒子路径唯一且无其他活动炉石客户端的情况下重启 HSAng.exe；不会关闭炉石或战网。取消按钮可中断整个恢复流程。
5. 局面或推荐连续异常超过 3 秒后自动重连脚本；连续 3 次仍未恢复才请求盒子恢复。恢复循环不会把异常直接变成“已停止”，直到用户主动停止、取消令牌或命中用户配置的策略停止条件。
6. 已提交但尚未观察到局面变化的动作会跨重连保留门禁，避免重复出牌；只有观察到确认变化才清除门禁。
7. 刷新卡组时先在 UI 线程读取路径，再交给后台任务，避免“另一个线程拥有该对象”异常。
8. Automation 的每一代连接均使用独立 generationToken；取消、重连和盒子恢复不会误用已结束代的取消令牌。

安全边界
- 自动恢复只操作已确认的 HSAng.exe；多盒子、路径不一致、PID 重用、目标炉石身份变化时拒绝操作。
- 安装器要求炉石退出，采用临时文件、哈希校验和备份清单，保留其他 BepInEx 插件。
- 只读模式不自动重启盒子、不写入游戏目录、不提交游戏动作。
- 本次未打包 ZIP，桌面副本仅用于源码审阅和测试复核。

验证
- dotnet build src\\HsAuto\\HsAuto.csproj --no-restore：成功，0 错误（保留已有编译器警告）。
- SelfTest：193/193 passed；报告见 selftest-recovery.json。
- GUI Smoke recovery-smoke4：通过；只使用隔离夹具，不启动真实炉石/盒子，不执行关机。

9. 盒子 AI 建议连续 3 秒不可用时先自动重启脚本生成；下一代仍没有建议才安全重启炉石盒子。盒子重启完成后由恢复循环自动重新初始化脚本，不需要用户再次点击。普通 Bridge/进程异常仍使用连续 3 次脚本重连后才重启盒子的策略。
